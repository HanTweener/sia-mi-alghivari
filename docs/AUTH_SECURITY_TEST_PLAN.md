Pelaksanaan kelak memakai fixture sintetis akun aktif/nonaktif, kombinasi role, dua kelas/anak, relasi dicabut, delegasi aktif/kedaluwarsa dan status draft/finalized/published/revoked. Gunakan credential uji yang dibuat aman saat eksekusi; jangan mencantumkan password/token/sesi pada repository atau laporan. Prinsip berikut menentukan assertion, tanpa mengubah aturan kanonis:

- AS-01/04/05 memeriksa keadaan sesi server dan header/cookie aktual, bukan hanya redirect atau HTTP200. Cookie sesi host-only/HttpOnly diuji terpisah dari cookie XSRF yang dapat dibaca adapter. Eksekusi browser HTTPS lokal yang dikonfigurasi tidak memakai domain publik atau akun nyata.
- AS-02/03 menguji bentuk respons dan penanganan akun tidak ada/nonaktif serta batas kebijakan yang telah disetujui. Jangan menilai kesamaan waktu dari satu sampel atau memakai sleep tetap sebagai bukti bebas enumerasi; metode pengukuran, toleransi dan keterbatasan dicatat tanpa klaim constant-time seluruh request. Tidak memilih angka limiter/panjang/hash baru melalui tes.
- AS-06 membedakan origin same-origin HTTPS, cross-origin, browser tanpa Fetch Metadata, dan fallback token invalid/hilang. Laravel 13 dapat menerima same-origin sebelum token; 419 bukan harapan universal. Pengecualian forgery default `/broadcasting/auth` diverifikasi bersama middleware yang benar-benar dipilih. Respons auth broadcaster tetap format adapter; bukan envelope JSON aplikasi. Tidak menambahkan allowSameSite/wildcard untuk membuat tes hijau.
- AS-08/15: injeksi audit/inbox gagal -> password/proof/pending rollback. Email/queue sesudah commit gagal bukan rollback password; modal wajib masih pending dan dapat dilanjutkan dengan proof/fresh login. Uji pilihan No terhadap hash-mismatch middleware dan Yes terhadap generation/revocation/race.
- AS-09 menggunakan dua koneksi/request dengan urutan terkoordinasi: revoke commit lebih dahulu berarti mutasi sensitif berikutnya ditolak; mutasi sah yang commit dahulu tercatat sebelum revoke. Uji request lama yang selesai sesudah pencabutan agar tidak membuat sesi valid kembali. Waktu dikontrol untuk expiry/delegasi/step-up; tidak menambahkan kolom auth_version atau menebak strategi fisik. Read/stream yang sudah mengirim data sebelum revoke tidak diklaim dapat ditarik kembali.
- AS-10..16 memeriksa body/proyeksi/count/file dan efek SQL dengan policy nyata. Principal+teacher hanya menulis penugasannya; wali kelas hanya memfinalisasi/memublikasikan binaan; MA saja mengubah KKM/bobot global. Data Entry+teacher dapat D/P pada mapel sendiri melalui grant guru, bukan delegasi Data Entry. Hak mandiri profil tetap berlaku bagi semua role. SQL runtime tetap boleh SELECT/INSERT audit melalui kebutuhan service internal, tetapi tidak UPDATE/DELETE audit atau DDL; pengguna tidak mempunyai route CUD audit.
- AS-17 memakai integrasi Reverb/worker untuk subscription dan hint, lalu HTTP terkini untuk daftar/count/tujuan. Socket lama mungkin tetap hidup; tidak menuntut disconnect instan sebagai satu-satunya bukti revoke. Payload minimal dan penolakan fetch berizin diperiksa; stub/socket palsu tidak membuktikan integrasi hidup.
- AS-18 tetap step-up administratif terpisah. AS-20 sekarang OTP email D25 wajib, bukan kondisional/N/A; mail fake/clock/race/hash/purpose diuji tanpa mail nyata. Bootstrap dan email hilang tetap OPEN, tidak membuka fallback SQL/password default.

Jalankan pengujian backend pada engine target dengan akun runtime; akun migrator hanya untuk persiapan resource uji. Uji negative grant SQL dengan koneksi runtime yang sesungguhnya. Browser melengkapi tes HTTP/integrasi untuk keyboard/paste/password manager, error/sesi habis dan pembersihan state; aksesibilitas tidak digantikan satu respons status. Fixture/cleanup hanya pada resource uji yang diverifikasi, bukan database demo aktif atau volume operator.
