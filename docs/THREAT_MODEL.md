# Threat Model — SIA MI ALGHIVARI

## Scope, release revision and owners

Diperbarui: 29 Oktober 2026. Status: **PROPOSED / blueprint**, implementasi **NOT STARTED**, seluruh pengujian **NOT RUN**. Belum ada commit/release/image yang dapat diidentifikasi. Pemilik keputusan produk dan penerimaan risiko: pemilik proyek. Pengembang/penguji implementasi dan reviewer rilis belum ditugaskan.

Cakupan: satu aplikasi sekolah dengan login lokal, role rangkap, data akademik, penilaian/kehadiran, perkembangan wali, snapshot/file rapor, naik/lulus, audit, inbox dan Reverb/Echo. Topologi demo yang direncanakan: Compose lokal, CI/GHCR, runner deployment tepercaya dan Cloudflare Tunnel. [PRD](PRD.md), [arsitektur](ARCHITECTURE.md), [stack](TECH_STACK.md), [deployment](DEPLOYMENT_ARCHITECTURE.md) dan [pipeline](CICD_PIPELINE_SPEC.md) tetap mengikuti status persetujuan masing-masing.

Yang dimodelkan adalah risiko rancangan, **bukan temuan kerentanan pada aplikasi yang sudah ada**. Dampak/kemungkinan bersifat penilaian kualitatif sementara; belum ada data insiden, pengukuran serangan atau bukti kontrol bekerja. Tidak menambahkan social login, MFA, multi-tenant atau layanan keamanan berbayar untuk mengisi template.

## Data assets, actors, trust boundaries and flows

| Aset | Sensitivitas dan batas penggunaan |
| --- | --- |
| Akun, hash password, sesi dan bukti step-up | Rahasia autentikasi; tidak dapat dibaca lewat aplikasi, audit domain, log, props atau event. Penyimpanan internal framework mengikuti kebutuhan verifikasi, bukan ekspor pengguna. |
| Identitas/kontak siswa, wali dan staf; foto | Data pribadi, termasuk anak; proyeksi minimum untuk tugas. Demo/fixture sintetis, tidak menyalin biodata/kredensial laporan KP. |
| Nilai, kehadiran dan hubungan kelas/anak | Data akademik terbatas; draft, published/finalized dan histori mempunyai aturan akses berbeda. |
| Snapshot/PDF rapor dan keputusan naik/lulus | Dokumen berintegritas tinggi; snapshot final tidak ditimpa, approval principal terpisah dari apply, file privat. |
| Audit dan inbox | Riwayat yang dapat mengungkap identitas/perubahan; pembaca tetap difilter per event/field/scope terkini. Audit append-only untuk akun aplikasi, inbox bukan salinan credential. |
| Database, file privat, backup, key dan image | Dibutuhkan untuk kontinuitas dan integritas. Credential DB/runtime/migrator/runner/Tunnel/registry terpisah dan tidak masuk Git/image/log. Backup diperlakukan sesensitif sumbernya. |

Aktor: pengguna sah dengan role/assignment terbatas, pengguna yang mencoba memperluas akses, penyerang internet setelah demo dipublikasikan, pemegang sesi curian, serta operator/runner/server dengan kewenangan infrastruktur. Server/DBA yang telah dikuasai mempunyai kemampuan di luar akun aplikasi; tidak ada klaim audit mustahil dimodifikasi oleh penguasa storage.

Batas kepercayaan dan alur:

1. Browser → origin aplikasi melalui HTTPS/Tunnel: form, ID, header dan file adalah input tidak tepercaya. Cookie mengidentifikasi sesi; server memuat akun/grant terkini. Pilihan menu tidak mengubah izin.
2. HTTP/action → database/storage: query diproyeksikan sesuai scope; mutasi bisnis+audit+inbox satu transaksi. PDF/file ditangani di luar lock DB melalui sumber yang dipercaya; DB dan filesystem tidak dianggap satu transaksi ACID.
3. Commit → database queue/worker → Reverb → Echo: penerima diperiksa ulang, sinyal minimal menunjuk inbox; fetch isi tetap melalui policy. Realtime adalah best effort, bukan sumber kebenaran atau jaminan exactly-once.
4. HTTP/file → wali: Perkembangan Belajar membaca aktivitas yang dibagikan/disahkan tanpa menunggu rapor; Rapor Online membaca hanya versi published anak. Semua jalur daftar/count/file/audit/notifikasi harus menjaga pemisahan itu.
5. PR/CI → image GHCR → runner lokal → Compose demo: build tak tepercaya tidak mendapat secret/runner deployment; artefak terverifikasi dikunci digest. MySQL, Docker API, runner dan port administrasi tidak dipublikasikan lewat Tunnel.
6. Database/file → backup → restore: akses operator dibatasi; rehearsal pada resource terisolasi. Volume persisten bukan backup, dan image lama tidak mengembalikan skema/data secara otomatis.

## Threat register

**Cara membaca kolom Existing control:** belum ada kontrol aplikasi yang diimplementasikan atau diverifikasi. Semua kontrol yang tertulis adalah **usulan**, dengan hasil verifikasi NOT RUN. Owner di bawah adalah tanggung jawab rencana, bukan penugasan yang sudah terjadi. Tidak ada tenggat penerimaan risiko yang sudah disepakati.

D-25 menggantikan D-23/D-24: password sementara emailed/forced change dan OTP email Fouladgar. Email langsung verified oleh Master; modal pilihan sesi setelah password tersimpan wajib, reset login biasa/profil current device tetap login. Angka parameter/provider dan detail integrasi belum final. [Lifecycle kanonis](RECOVERY_AND_STEPUP_PLAN.md).

## Release blockers, risk acceptances, independent review

Penerimaan implementasi terkait diblokir bila ada bocoran data anak/credential, privilege escalation, bypass approval principal, audit tidak atomik, nilai/snapshot salah, file privat terbuka, sesi yang semestinya dicabut masih diterima, atau migrasi/restore berisiko kehilangan data tanpa mitigasi/bukti. Tidak tersedianya pengujian kritis bukan PASS dan tidak diselesaikan dengan menghapus skenario.

Keputusan terbuka: parameter password/hash/OTP/proof/limit/retensi/provider D25, bootstrap/mailbox hilang, idle/absolute/step-up dan middleware/race, broadcaster, Q6 allowlist/delegasi/aktivasi usulan penugasan serta aktor/waktu prepare/apply. D-26/D-27 handover/frozen roster dan D-28 koreksi/revisi/pencabutan rapor telah dipilih; implementasi belum diverifikasi. Email Master-attested bukan bukti pengguna menguasai mailbox; No mempertahankan sesi yang mungkin dicuri. Semua kontrol runtime NOT RUN.

Hipotesis yang perlu diuji kelak: policy bersama dapat menjaga proyeksi di semua entry point; serialization/unique mencegah race akademik tanpa lock terlalu lama; hint minimal+fetch menjaga data saat socket tertinggal; sesi server dapat dicabut tanpa resurreksi request lama. Belum ada hasil pengukuran/pengujian untuk menerima hipotesis tersebut.

Pemilik meninjau risiko residual dan menentukan keputusan/tenggat yang nyata; belum ada pengecualian risiko atau persetujuan rilis yang diberikan oleh dokumen ini. Review blueprint dilakukan terpisah dari pembuktian implementasi. Sebelum rilis publik yang relevan, lakukan review keamanan sesuai risiko dan verifikasi aktual; laporan [security](SECURITY_VERIFICATION_REPORT.md) dan [identity](IDENTITY_SECURITY_VERIFICATION_REPORT.md) baru diisi dengan hasil faktual setelah eksekusi. Tidak menjalankan scanner pada domain/host eksternal, membuat akun atau merotasi credential pada tahap ini.

Referensi primer diperiksa 28 Oktober 2026: [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) untuk batas akses dan [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) untuk lifecycle sesi. Kontrol dan hipotesis di atas adalah rancangan proyek, bukan sertifikasi atau kontrol yang sudah berjalan.
