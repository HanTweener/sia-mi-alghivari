Threshold latency berlaku untuk sampel valid dengan response/error handling benar. Denominator eligible tidak membuang timeout, network error atau unexpected 4xx/5xx. Laporkan p50/p95/p99 untuk respons selesai beserta timeout, error, dropped iterations dan good/eligible; timeout tanpa durasi akhir ditulis censored pada deadline, tidak dianggap respons cepat. Tes negatif yang memang mengharapkan403/409/422/429 dikelompokkan terpisah, tidak dicampur untuk memperindah success rate. Bug izin/rumus/audit/file memblokir walaupun latency cepat.

Minimal100 operasi eligible per jenis/kondisi untuk pembandingan p95 pilot merupakan usulan ukuran sampel, bukan pembuktian statistik penuh. p99 pada sampel kecil hanya eksplorasi; catat N, durasi, sebaran, cold/warm, error dan variasi antar-run. Sampel kurang berarti INCONCLUSIVE/NOT VERIFIED untuk target, bukan PASS. Jangan merata-ratakan p95 antar-route/run; simpan distribusi mentah atau histogram kompatibel untuk agregasi yang sah.

## Field CWV vs lab tests

Belum ada field/RUM aplikasi inti. Browser lab, Lighthouse kandidat, React profiler atau trace prototipe tidak membuktikan pengalaman pengguna lapangan. PB-08 mengukur interaksi spesifik di lab, tidak mengklaim field INP atau kelulusan CWV. Jika field telemetry kelak diotorisasi, tetapkan consent/minimasi dan sampling, gunakan agregat tanpa identitas siswa/URL ID/isi input, pisahkan p75 field dari p95 lab. Threshold metrik field dan periode sampel dibahas saat data tersedia; tidak memasang layanan RUM dari blueprint ini.

Aset/fonts dan cache publik hanya boleh diterapkan pada aset statis yang sesuai. Props personal, nilai, audit, inbox dan PDF tetap private/no-store sesuai [API_CONTRACT](API_CONTRACT.md); peningkatan cache tidak melewati current authorization atau mengubah snapshot. Localhost mengisolasi server; pengukuran Tunnel menambahkan internet/edge/browser, keduanya berlabel terpisah. Angka lokal tidak dipindahkan menjadi klaim performa publik.

## Exceptions and review frequency

Tinjau usulan ini setelah baseline pertama pada host tercatat, sesudah perubahan query/indeks/rumus/renderer/props, serta sebelum penerimaan integrasi dan demo publik. Ukur sebelum/sesudah dengan data, beban dan host sama; pilih perbaikan paling kecil yang menunjukkan dampak tanpa mengurangi akses, audit atau validasi. Tidak ada exception disetujui. Perubahan target memerlukan alasan, owner, tanggal dan persetujuan aktual; hasil lambat tetap dicatat, bukan dihapus dengan mengganti ambang setelah run.

Seluruh target kapasitas, matriks device/network final, batas batch/body/worker dan waktu layanan masih PROPOSED/OPEN; jadwal/retensi backup D-31 diterima tetapi belum diuji; lihat [recovery](DATA_RECOVERY_PLAN.md) dan SLO_SLI. Target formal RPO/RTO di luar scope demo (D-32); backup/restore fungsional tetap perlu dibuktikan. Jendela demo lokal bukan komitmen24/7. Tidak ada benchmark/toolchain/command runtime dieksekusi pada penyusunan ini.
