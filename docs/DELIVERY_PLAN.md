# Delivery Plan — SIA MI ALGHIVARI

Diperbarui: 29 Oktober 2026. Pemilik hasil/keputusan: pemilik proyek. Status: **PROPOSED / blueprint**. Rencana ini disusun pada dokumentasi urutan 1; fokus dokumentasi terbaru mengikuti PROJECT_STATE.md. Seluruh implementasi M1–M5 **NOT STARTED**; seluruh pengujian aplikasi **NOT RUN**.

## Goal / outcome

Menyusun pembangunan bertahap SIA satu sekolah dari nol, dengan hasil kecil yang dapat diverifikasi: akses dan pencatatan perubahan → persiapan akademik → aktivitas guru dan pemantauan wali → rapor → keputusan naik/lulus → demo portofolio sintetis.

[PRD](PRD.md) menetapkan kebutuhan; [roadmap](ROADMAP.md) menetapkan M0–M5; [PROJECT_STATE](PROJECT_STATE.md) mencatat kondisi aktual. Dokumen ini mengatur ketergantungan dan kepemilikan penulisan, bukan bukti fitur selesai atau instruksi memulai implementasi.

Hasil penyusunan urutan 1: dua dokumen tersebut memisahkan fakta, keputusan, pekerjaan rencana, ketergantungan dan bukti yang belum tersedia; indeks dan konteks singkat disinkronkan seperlunya. Tidak membuat source aplikasi, konfigurasi, schema, branch, workflow atau deployment. Implementasi membutuhkan instruksi pemilik; keputusan terbuka diselesaikan untuk slice terkait, tanpa memaksa seluruh fitur diputuskan sekaligus.

## Cost/concurrency and isolation policy

Tim penyusun urutan 1: agen utama menyusun PROJECT_STATE dan mengintegrasikan; subagen penulis menyusun DELIVERY_PLAN; subagen terpisah menelaah baca-saja. Ini koordinasi dokumentasi, bukan penugasan implementasi atau klaim review keamanan independen. Pembagian pekerjaan dokumentasi lanjutan mengikuti tugas aktual, bukan dibatasi penugasan historis ini.

Paralel digunakan hanya untuk path/tanggung jawab yang tidak berbenturan dan memberi manfaat nyata. Cabang DAG menunjukkan urutan data, bukan kewajiban menambah agen. DP-23 kalkulator murni dapat terpisah dari UI attendance; DP-13 dan akademik tetap bergiliran bila menyentuh routes/model/layanan bersama. DP-24 → DP-25 sengaja berurutan agar pola roster/validasi dibuktikan dahulu tanpa dua writer pada integrasi input kelas.

Sebelum pekerjaan kode kelak, integrator mencatat path spesifik dan satu penulis aktifnya. Writer tidak mengembalikan perubahan orang lain; konflik diselesaikan pada kontrak bersama, bukan dengan menimpa file. Reviewer membaca dan memberi temuan; penulis melakukan perbaikan di path miliknya. Tidak mewajibkan worktree/agen/spesialis tambahan untuk setiap CRUD.

Dev, CI dan demo mempunyai database, credential, volume serta resource terpisah; semua fixture sintetis. Pengujian rollback/race/load/restore hanya pada resource uji yang jelas, bukan database demo aktif atau endpoint publik. Waktu, relasi, state dan ukuran fixture dicatat; command belum tersedia tidak dianggap terverifikasi.

Tidak memperkirakan penghematan token, biaya cloud, kapasitas host atau durasi delivery tanpa pengukuran. Anggaran proses/container dan beban uji disesuaikan setelah toolchain serta spesifikasi host benar-benar diketahui. Memadatkan source atau mengurangi tes izin bukan penghematan yang diterima.
