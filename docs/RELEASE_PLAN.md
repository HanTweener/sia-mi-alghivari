# Release & Operations Plan - SIA MI Alghivari

Owner keputusan: pemilik proyek; operator rilis, penguji dan reviewer belum ditunjuk. Ditinjau penyusun 29 Oktober 2026. Status PROPOSED blueprint; implementasi inti NOT STARTED dan seluruh rilis/gate/smoke/operasi NOT RUN.
Target environment: demo portofolio sintetis pada satu host lokal/Compose. Release identifier, commit, image digest, ID workflow dan URL aktif belum tersedia. Image berkonfigurasi production tidak menjadikan target ini produksi sekolah. Dokumen tidak mengotorisasi instalasi, provisioning atau deployment sekarang.

## 1. Deployment topology

Sumber alur adalah [CICD_PIPELINE_SPEC](CICD_PIPELINE_SPEC.md), [DEPLOYMENT_PLAN](DEPLOYMENT_PLAN.md), [DEPLOYMENT_ARCHITECTURE](DEPLOYMENT_ARCHITECTURE.md), [ENVIRONMENT_SPEC](ENVIRONMENT_SPEC.md) dan [TECH_STACK](TECH_STACK.md). Dev lokal → PR/main tepercaya → GitHub-hosted CI/build → GHCR image immutable → runner deployment lokal terbatas → Compose app/queue/Reverb, MySQL dan storage privat → Cloudflare Tunnel HTTPS/WSS saat mode publik diaktifkan. Satu image digest yang lolos pemeriksaan dipakai app, worker dan Reverb; konfigurasi deployment tepercaya serta versi schema/job ikut manifest.

Dev/CI/demo terpisah project/network/database/volume/credential; branch atau profil Compose saja bukan isolasi. Rehearsal migration/runtime memakai resource lokal/CI sementara dengan engine target dan data sintetis, bukan staging permanen baru. Judul staging/production pada template [RELEASE_RUNBOOK](RELEASE_RUNBOOK.md) dijelaskan sebagai rehearsal dan rollout demo; keduanya tidak memberi status formal staging_verified/production_verified sekolah. Jika gate framework dipakai kelak, petakan hanya lingkungan/bukti yang benar-benar ada, jangan mengisi record produksi palsu atau menghapus check wajib agar lolos.

PR/fork tidak dapat memakai runner Docker/secret demo; runner lokal hanya menjalankan jalur deployment main yang telah diotorisasi. Proteksi branch, scope runner, job permissions, action pinning dan asal bukti harus benar-benar dikonfigurasi sebelum CD aktif. Satu deployment aktif per target, antrean rilis tidak membatalkan migrasi berjalan atau menimpa rilis baru dengan kandidat usang. Publikasi GHCR dan pull image belum membuktikan target sehat.

Secret diinjeksi runtime melalui mekanisme aman yang dipilih operator; APP_KEY persisten, credential DB, registry dan Tunnel/Reverb tidak dicetak ke manifest, log, report, image layer atau VITE props. Identitas migrator/restore terpisah dari runtime; runtime tidak DDL atau UPDATE/DELETE audit. Semua migrasi mengikuti [DATABASE_MIGRATION_PLAN](DATABASE_MIGRATION_PLAN.md): kompatibilitas schema/job direhearsal, perubahan destruktif di luar CD biasa, tidak ada fresh/reset/seed ulang/down massal pada data demo persisten.

## 3. Deployment steps

Rincian operasional di RELEASE_RUNBOOK; daftar ini menjaga urutan dan definisi keberhasilan. Seluruh langkah NOT RUN, command deployment aplikasi belum dikonfigurasi dan tidak dicantumkan sebagai perintah siap pakai.

1. Validasi RP-01..09, identitas environment, SHA/digest/config calon dan versi aktif/sebelumnya, bukti CI serta owner/jendela. Ambil lock deployment, cek kandidat masih sesuai kebijakan freshness; hentikan jika runner/host/registry/bukti tidak tersedia. Tarik dan verifikasi artefak sebelum menghentikan versi sehat.
2. Klasifikasikan perubahan schema/job/config. Gunakan rehearsal terisolasi yang sudah tercatat, siapkan recovery set serta rencana image lama/roll-forward. Bila backup atau migrasi memerlukan quiesce, tutup penulisan dan drain/hentikan seluruh writer terkait, worker/render dan migrator lain dengan hasil akhir yang jelas. Maintenance UI saja tidak menjamin DB/file konsisten.
3. Ambil backup terkoordinasi DB+file privat dan verifikasi manifest/checksum sesuai recovery plan; gunakan migrator tunggal untuk perubahan kompatibel yang dipilih. Catat schema yang benar-benar diterapkan; DDL tidak dianggap rollback sebagai satu transaksi domain. Stop pada kegagalan/unknown state, tanpa down/fresh otomatis.
4. Perbarui app, queue dan Reverb ke digest sama dengan konfigurasi tepercaya yang cocok; jaga DB/storage/key persisten dan waktu shutdown/job yang dipilih. Jangan menjalankan startup yang mengulang migration/seed atau mengeksekusi job tak kompatibel. Publikasi aset dan URL Echo yang tertanam harus cocok dengan build, bukan diedit ke secret di browser.
5. Pertahankan pembatasan akses umum sampai smoke internal required lulus memakai akun sintetis sah tanpa bypass policy, lalu periksa HTTPS/WSS publik jika target publik diaktifkan. Verifikasi login/akses positif dan negatif, satu mutasi sintetis baru berizin beserta audit/inbox, read-state tanpa rekursi, queue/hint/reconnect, perkembangan dan file rapor sesuai state. Tidak mengulang publish/apply data lama untuk menghasilkan notifikasi; tidak menghapus audit hasil smoke.
6. Buktikan RP-10, amati error/latency/resource serta hasil bisnis terhadap baseline/jendela terpilih, rekam status berhasil/gagal/terdegradasi beserta bukti dan tindak lanjut. Lepas lock setelah keadaan akhir target terdokumentasi. GHCR publish, container running atau halaman login200 tidak cukup untuk memberi verdict berhasil.

Jika belum ada data/fitur untuk smoke required, laporkan gap; jangan mengganti server dengan prototipe atau status sukses dummy. Failure injection/destructive drill dilakukan pada resource rehearsal, bukan demo aktif sebagai pemeriksaan rutin.

## 4. Rollback / recovery

Kebocoran hak/secret, nilai/snapshot salah, audit/inbox tidak atomik, histori rusak, login/file wajib gagal, migrasi unknown atau smoke worker/WSS gagal menghentikan promosi. Hint Reverb gagal dapat membuat layanan terdegradasi dengan inbox persisten tetap benar, tetapi rilis yang mensyaratkan realtime tetap belum berhasil sampai diperbaiki/diverifikasi. Saat insiden operasional, tindakan containment mengikuti dampak, bukan memaksa restore DB hanya karena socket putus.

CI/build/push/pull gagal sebelum target diubah berarti pertahankan versi aktif; host/runner offline bukan deployment sukses. Jika sudah mengubah target, catat digest app/queue/Reverb, schema dan job aktual sebelum memilih tindakan. Gunakan [RUNBOOK](RUNBOOK.md) untuk diagnosis aman dan [DATA_RECOVERY_PLAN](DATA_RECOVERY_PLAN.md) untuk restore; operator tidak mengulang request mutasi yang hasil commit-nya belum pasti.

Image rollback hanya bila schema, data, config dan job tetap kompatibel dengan digest sebelumnya yang tersedia serta rencana telah diuji. Jika tidak kompatibel, tahan promosi/tulis sesuai dampak lalu roll-forward atau restore terkoordinasi melalui otorisasi target yang tepat. Kembali ke image lama tidak membatalkan DDL, mengembalikan file atau memulihkan acknowledged writes. Restore dapat kehilangan perubahan dan menghidupkan grant/password lama; rekonsiliasi current grants, sesi/step-up dan queue sebelum akses dibuka.

Threshold performa pilot masih usulan; target formal RPO/RTO tidak menjadi gate demo portofolio (D-32); jadwal/retensi3lokal7harian4mingguanDrive diterima D-31, seluruh hasil operasional belum terukur. Sebelum aktivasi, pilih deadline shutdown/migration/health/smoke/observasi/abort dan tanggung jawab aktual; tidak membuat retry/restart tak terbatas untuk mengejar hasil hijau. Rilis gagal dicatat apa adanya, pemulihan diverifikasi lalu keputusan lanjut dicatat. Komunikasi insiden memakai catatan aman yang disetujui; tidak mengirim email/WhatsApp atau notifikasi ke pihak lain secara otomatis dari rencana ini.
