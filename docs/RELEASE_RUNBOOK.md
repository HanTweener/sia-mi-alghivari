# Release Runbook - SIA MI ALGHIVARI

**Release owner:** pemilik proyek; operator/pelaksana dan reviewer rilis belum ditunjuk. **On-call:** belum ada layanan/jadwal 24 jam. **Environment:** target rencana demo sintetis satu host Compose; rehearsal memakai resource lokal disposable terpisah. Revisi 29 Oktober 2026, status **PROPOSED / blueprint**; seluruh deployment, smoke dan drill inti **NOT RUN**.

Dokumen mengatur urutan rilis, bukan konfigurasi siap dijalankan. Seluruh command/script aplikasi **BELUM DIKONFIGURASI**; gunakan langkah logis di bawah saat implementasi telah diotorisasi dan command nyata diverifikasi. Tidak ada perubahan GitHub/registry, migrasi, container, secret, DNS atau Tunnel yang dijalankan sekarang. Referensi [facelift-v2](support/facelift-v2/README.md) hanya prototipe desain memori, bukan artefak runtime/otorisasi server.

## Preconditions

Acuan: [CI/CD](CICD_PIPELINE_SPEC.md), [rencana deployment](DEPLOYMENT_PLAN.md), [topologi](DEPLOYMENT_ARCHITECTURE.md), [environment](ENVIRONMENT_SPEC.md), [migrasi](DATABASE_MIGRATION_PLAN.md), [pemulihan data](DATA_RECOVERY_PLAN.md), [kualitas kode](CODE_QUALITY_PLAN.md), [tes](TEST_PLAN.md) dan [SLO/SLI](SLO_SLI.md). Rencana rilis terkait ada pada [RELEASE_PLAN](RELEASE_PLAN.md). Dokumen saling merujuk; tidak membuat gate/platform deployment baru.

- **Otoritas:** persetujuan blueprint CD belum mengaktifkan deployment. Aktivasi pertama runner/proteksi main, akses host, secret, domain/Tunnel dan CD memerlukan instruksi/otorisasi operasional pemilik. Setelah lingkup CD rutin benar-benar diotorisasi, rilis kompatibel dari main tepercaya dapat berjalan otomatis mengikuti gate; tidak menambah pertanyaan izin per rilis dalam lingkup itu. Produksi sekolah, migrasi destruktif dan cutover/restore data aktif tetap keputusan terpisah.
- **Sumber tepercaya:** hanya commit main yang diterima melalui proteksi/review dan pemeriksaan wajib. CI PR serta hasil merge main harus relevan terhadap revisi aktual; bukti SHA lain atau prototipe tidak menggantikan bukti target. Dev/fork/PR tak tepercaya tidak mengakses runner deployment atau secret demo.
- **Artefak:** satu image rilis dibangun dan diperiksa dari lockfile/revisi yang dicatat, disimpan pada GHCR dan dikunci digest. Manifest rilis mencocokkan commit/digest, schema/migrations, format job, konfigurasi deployment dan aset frontend; key runtime tidak masuk build. Jika sudah ada versi aktif, digest/akses image sebelumnya tersedia sebelum menghentikannya, bukan mengandalkan latest. Pada bootstrap yang terbukti kosong, catat previous=tidak ada; jangan mengarang image lama atau fallback yang belum pernah diuji.
- **Gate:** seluruh pemeriksaan engineering, regresi, QA, keamanan/identitas, database, build/image dan review yang berlaku bagi lingkup rilis mempunyai hasil nyata revisi target. NOT RUN, command kosong, required check terlewat atau risiko kritis belum diselesaikan menghalangi rilis terkait. Q6/visual Q7/lifecycle/lifecycle tidak diaktifkan dengan dugaan untuk meloloskan gate.
- **Target:** host/project/database/network/volume demo terverifikasi berbeda dari dev/CI/rehearsal. Secret/runtime, key persisten, storage, kapasitas, runtime SQL grant, pull registry dan trusted proxy/origin sesuai environment. Database/runner/Docker API tidak dipublikasikan; debug mati, aset terkompilasi tanpa Vite/source dev.
- **Data dan operasi:** untuk upgrade target berdata tersedia recovery set DB+file yang konsisten; seluruh aktivasi tetap memerlukan bukti rehearsal bootstrap/restore fixture sesuai T-19/DBV-24/25. Bootstrap baru harus membuktikan DB/storage target kosong dan resource benar, mencatat backup target sebelumnya=tidak ada serta menyiapkan abort aman tanpa menghapus resource lain. Backup pertama setelah inisialisasi berizin direncanakan sebelum target bergantung pada persistensi; tidak memalsukan backup lama. Policy backup/retensi/key recovery, batas lock/timeout/retry, jendela dan metode observasi ditetapkan sebelum aktivasi. SLO performa masih proposal dan bukan bukti kesiapan; target formal RPO/RTO tidak berlaku pada portofolio D-32, restore fungsional tetap wajib. Pilih operator, jalur eskalasi dan keputusan abort sebelum eksekusi.

## Staging procedure

Heading ini dipertahankan, tetapi tahap proyek sekarang adalah **rehearsal lokal disposable yang menjalankan fungsi pemeriksaan staging**, tanpa membuat staging permanen. Catat hasil sebagai rehearsal terisolasi; jangan menyebut `staging_verified` formal tanpa target staging aktual, atau menganggap demo sebagai produksi sekolah terverifikasi.

1. **Siapkan run terisolasi.** Verifikasi identitas host/DB/volume/network dan manifest fixture sintetis sebelum setup/teardown; tidak menyalin secret demo. Catat image/engine digest, schema awal, versi tool dan konfigurasi nonsecret. Rehearsal tidak memakai Tunnel/penerima nyata atau outbound effects yang tidak diotorisasi.
2. **Gunakan artefak calon yang sama.** Jalankan image berdigest yang sudah diperiksa, bukan rebuild lain dari source berubah. Buktikan startup/config/storage/DB dengan credential runtime; healthcheck/port terbuka saja belum cukup. Source/prototipe atau Git branch bukan identitas artefak rilis.
3. **Rehearse schema/job.** Uji bootstrap dan upgrade dari versi sebelumnya, termasuk snapshot/audit/inbox/file yang sudah ada. Migrator terpisah dari credential app dan tidak berjalan otomatis pada startup app/queue/Reverb. Jika timeout/DDL gagal, periksa schema/migration aktual sebelum mencoba langkah lain; jangan menganggap seluruh DDL rollback.
4. **Rehearse pemulihan.** Simulasikan jendela tanpa writer, backup DB+file+manifest, restore ke resource baru dan rollback image kompatibel/roll-forward. Jangan menjalankan fresh/reset/seed ulang pada data aktif. Pisahkan prosedur fixture disposable yang memang diotorisasi dari prosedur rilis rutin.
5. **Verifikasi perjalanan aktual.** Login/sesi, negatif lintas anak/kelas/role, profil tanpa eskalasi, input satu aktivitas sintetis baru yang sah, row domain+audit+inbox atomik, state/versi dan file berizin. Bila fitur tersedia, periksa finalized belum published, PDF siap/snapshot benar serta approval tidak apply. Pengujian fitur yang belum tersedia dicatat sebagai gap cakupan, bukan PASS.
6. **Verifikasi worker/realtime dan kegagalan.** Gunakan job aman yang merujuk operasi sintetis tersebut; pastikan worker/Reverb/private channel/Echo dan refetch/reconnect bekerja, termasuk scope dicabut dan hint duplikat. Injeksi rollback/commit-before-enqueue/file gagal hanya di rehearsal. Pulihkan layanan sebelum smoke akhir; jangan menganggap stub socket sebagai bukti WSS nyata.
7. **Catat hasil dan bersihkan scope run.** Simpan output/trace aman serta kesenjangan, lalu teardown hanya resource rehearsal yang telah diverifikasi. Hasil gagal tetap disimpan. Rehearsal lolos belum mengotorisasi aktivasi publik atau menghapus gate target demo.

## Production procedure

Untuk lingkup sekarang, “production” pada heading berarti **menjalankan image runtime production pada demo portofolio sintetis**, bukan mengoperasikan data sekolah. Produksi sekolah **N/A untuk rilis demo ini** sampai ada scope/otorisasi tersendiri; seluruh kontrol keamanan, integritas dan deployment yang berlaku bagi demo tetap wajib. Status awal seluruh langkah belum dijalankan.

1. **Verifikasi asal pekerjaan dan ambil lock deployment tunggal.** Job hanya menerima main tepercaya dengan CI/build/scan wajib lolos pada commit target. Ambil giliran per demo; setelah menunggu, periksa lagi agar revisi usang tidak menggantikan yang lebih baru. Jangan membatalkan proses di tengah migrasi demi rilis berikutnya; timeout atau interupsi menjadi keadaan yang perlu diperiksa operator.
2. **Preflight sebelum mengganggu versi aktif.** Ambil image target berdigest dan pastikan akses digest sebelumnya bila memang ada versi aktif, konfigurasi deployment cocok, target environment benar, disk/DB/secret/key tersedia serta hasil gate/rehearsal masih berlaku. Catat state aktif dan schema awal; bootstrap kosong memakai previous=tidak ada dengan verifikasi resource/abort yang telah ditetapkan. Pull/build gagal atau host offline berarti calon belum siap; jangan menghentikan versi lama lebih dahulu.
3. **Tetapkan jalur schema dan recovery set.** Tinjau kompatibilitas image lama/baru serta job; gunakan perubahan expand yang telah diuji untuk CD rutin. Jika backup baru diperlukan, hentikan seluruh writer yang relevan, drain/stop worker dan render/upload/migrator, lalu capture DB+file pada cut yang konsisten sesuai DATA_RECOVERY_PLAN. Verifikasi arsip/manifes sebelum lanjut. Freeze bukan sekadar banner maintenance; jangan membiarkan old writer masuk selama capture/upgrade yang tidak kompatibel.
4. **Jalankan migrator tunggal yang terotorisasi.** Satu pemilik migrasi per target/rilis memakai identitas migrator khusus; app runtime tidak mendapat DDL. Terapkan hanya langkah schema yang sudah direhearsal. Tidak ada migration pada setiap startup/container, reset, seed ulang akun/data, dump secret atau rollback down massal. Jika hasil belum pasti, hentikan kelanjutan dan inspeksi keadaan aktual sebelum invocation ulang; tidak mengklaim exactly-once DDL.
5. **Perbarui proses terkendali.** Jalankan app, queue dan Reverb dari digest target yang sama, dengan volume DB/private storage serta APP_KEY lingkungan yang tetap. Beri waktu shutdown/drain sesuai kontrak job; jangan menjalankan payload lama pada kode yang tidak kompatibel. Pertahankan pembatasan akses umum sampai smoke internal required lulus; smoke memakai akun sintetis yang sah melalui akses uji terotorisasi, tanpa bypass policy. Tidak menghapus jobs/failed_jobs/inbox untuk membuat startup tampak bersih.
6. **Smoke internal dengan hak nyata.** Periksa app/DB/storage, schema/digest efektif, login akun uji dan penolakan guru/anak lain, grant runtime tidak U/D audit/DDL, serta satu operasi sintetis baru yang memang sah. Konfirmasi row bisnis, actor audit dan inbox penerima/scope setelah commit; tidak mengulang publish/apply objek final untuk menciptakan sukses palsu. Akun/fixture uji harus tersedia melalui proses yang sah, bukan membuat password/role lewat script rilis.
7. **Smoke file dan jalur publik yang diotorisasi.** Periksa PDF/avatar privat, state published/izin snapshot dan kegagalan akses langsung. Verifikasi HTTPS/domain/TLS/proxy/cookie, WSS/private-channel authorization, job diproses worker, hint minimal, reconnect/catch-up inbox dan badge dari server. Browser/UI serta data yang benar dibuktikan; HTTP200/halaman depan/container running/push GHCR saja bukan keberhasilan. Smoke publik bukan load/fault test pada Tunnel.
8. **Observasi dan putuskan hasil.** Ukur jendela yang ditetapkan sebelumnya, terapkan stop condition dan catat seluruh hasil/unknown. Jika smoke/gate target gagal, rilis belum berhasil walau image sudah terpasang; tahan promosi berikutnya dan pilih pemulihan yang sesuai. Baru catat “demo versi target terverifikasi untuk scope yang diuji” setelah semua bukti wajib tersedia; tidak melabelinya `production_verified` sekolah.
9. **Tutup catatan rilis.** Simpan target/calon/sebelumnya/aktif, SHA/digest, workflow/job ID, schema/job version, manifest recovery set, waktu freeze/deploy/smoke/observasi, actor/otoritas dan hasil aktual teredaksi. Jangan mencetak environment/credential atau membuat berkas evidence rekaan. Pastikan lock dilepas setelah keadaan target diketahui; kejadian tidak pasti diteruskan ke operator, bukan sukses otomatis.

## Abort and rollback/rollforward

Abort sebelum perubahan bila artifact/secret/target/backup tidak terverifikasi, revisi usang, gate wajib tidak tersedia/gagal, kapasitas tidak aman atau schema/job tidak kompatibel. Saat rilis, hentikan promosi/penulisan terdampak bila muncul kebocoran/eskalasi akses, nilai/snapshot salah, audit/inbox hilang, partial batch, file privat bocor, login rusak atau migrasi tidak pasti. Invariant kritis tidak menunggu budget error habis.

| Keadaan | Keputusan pemulihan yang direncanakan |
| --- | --- |
| CI/push/pull/preflight gagal sebelum write | Tidak melanjutkan; versi/data aktif dipertahankan. Retry hanya kegagalan transient aman dan terbatas dalam lingkup yang diotorisasi; cek revisi setelah antre. |
| App/worker/Reverb/smoke gagal, schema/job tetap kompatibel | Kembali ke digest sebelumnya yang sudah diuji dengan konfigurasi yang cocok, tanpa mengembalikan DB/file. Drain/restart proses secara terkendali dan ulang smoke; versi lama tidak diasumsikan aman setelah schema berubah. |
| DDL/migration atau kontrak job berubah/tidak pasti | Hentikan kelanjutan, catat schema/payload aktual; pilih perbaikan roll-forward yang ditinjau atau rencana kompatibilitas. Jangan menganggap SQL ROLLBACK/image lama membatalkan DDL/data atau retry statement terakhir pasti aman. |
| DB/file perlu dikembalikan | Operator mengikuti DATA_RECOVERY_PLAN: restore terisolasi, integritas/grant/credential/sesi/job direkonsiliasi, acknowledged writes hilang/unknown dilaporkan. Pengalihan target/data aktif membutuhkan otorisasi spesifik; bukan CD rollback otomatis. |
| Hanya sinyal realtime gagal sesudah commit | Data bisnis/inbox tetap sah, fetch catch-up; perbaiki proses/hint sesuai timeout/retry yang dipilih. Gangguan realtime dapat membuat smoke rilis gagal, tetapi tidak membatalkan commit bisnis atau mengulang mutasi untuk membuat hint. |

Rencana drill kegagalan berikut hanya expected outcome; **seluruh RR NOT RUN**, tidak ada command/revisi/report nyata yang diklaim. Gunakan bukti BF/DBV/CT/T-19 dan DR terkait, bukan suite atau file laporan baru demi penomoran:

- RR-01: gate main gagal/artefak digest salah/pull terputus → tidak merilis atau menghentikan versi aktif sebelum preflight lolos; source PR tidak mencapai runner.
- RR-02: dua deployment mengantre/revisi lebih lama terlambat → satu penulis target, tidak cancel migrasi di tengah, calon usang tidak mengganti versi baru.
- RR-03: backup tidak konsisten atau migrator terputus → promosi berhenti, schema/data nyata diperiksa, tanpa fresh/reset/down massal/anggapan DDL rollback.
- RR-04: kode baru gagal sementara schema/job kompatibel → digest lama dapat dipakai dengan volume tetap, lalu smoke login/izin/domain/audit/inbox/file/realtime membuktikan scope pulih.
- RR-05: restore diperlukan setelah write baru diakui → validasi isolated recovery set, laporkan kehilangan, invalidasi sesi/review grant/job, dan cutover hanya setelah otorisasi terpisah.
- RR-06: app HTTP200 tetapi transaksi audit/inbox, PDF atau WSS/reconnect gagal → rilis tetap belum berhasil; invariant kritis menghentikan alur dan kehilangan hint tidak menjadi rollback bisnis.

## Post-release monitoring

Pilih durasi pengamatan, workload/probe, cadence, timeout, operator dan kanal eskalasi sebelum rilis; sekarang belum ditetapkan. Gunakan [SLO_SLI](SLO_SLI.md), [PERFORMANCE_BUDGET](PERFORMANCE_BUDGET.md), [RUNBOOK](RUNBOOK.md) serta failure plan yang sudah ada. Angka pilot yang belum disetujui tidak berubah menjadi verdict otomatis dari runbook ini; tidak menambah monitoring stack, provider pesan atau jadwal on-call baru.

Amati perjalanan baca/tulis berizin dan hasil commit, error/timeout, DB/lock/disk, job age/failure, Reverb/dispatch gap, catch-up inbox dan file privat. Periksa operation/version/audit/inbox menggunakan fixture rilis yang aman; no-op atau halaman cache tidak dihitung sebagai transaksi baru sehat. Jika sistem memakai public window terdeklarasi, waktu maintenance/rilis/offline/unknown di dalamnya tetap dihitung sesuai SLI-01; operator tidak menghapus downtime setelah kejadian.

Pisahkan latency localhost dari Tunnel dan sampel rutin dari fault/load; angka dari sedikit smoke tidak membuktikan p95/SLO tercapai. Target render/queued hint/fetch punya titik awal berbeda sesuai kontrak SLI. Catat set yang dipakai serta perubahan yang diketahui belum tercakup sesuai data recovery; image rollback tidak membuktikan data pulih atau kehilangan nol. Target formal RPO/RTO tidak berlaku D-32.

Catat insiden serta hasil observasi sebelum menyerahkan target: versi aktif, pembatasan/gap, tindakan yang diambil, owner berikutnya dan kapan ditinjau lagi. Handoff/reviewer/approval hanya dicatat bila benar-benar ada. Produksi sekolah memerlukan scope/gate/otorisasi tersendiri; sekarang tidak ada deployment, smoke, drill RR atau hasil monitoring inti yang telah dieksekusi.

D-28 rilis/diagnosis: jangan membetulkan snapshot/audit melalui SQL atau membuka PDF lama saat revisi gagal. Pastikan koreksi/hold per siswa dan penolakan held/revoked/superseded diuji bersama lifecycle revision policy asli dan satu versi aktif; API-T55..57/DBV29..30 seluruhnya **NOT RUN**. Undo applied progression bukan fitur yang dibuka. Keputusan produk pada [ACADEMIC_FLOW](ACADEMIC_FLOW.md), tanpa otorisasi deploy/operasi baru.

D-30: [recovery](DATA_RECOVERY_PLAN.md) menetapkan arsip terenkripsi lokal lalu upload manual pemilik ke Google Drive. Preflight target berdata membedakan set lokal, upload_pending dan salinan offhost terverifikasi; jangan menganggap capture lokal sudah melindungi kehilangan komputer. Jika perubahan berisiko memerlukan set offhost baru, tunda perubahan sampai upload/verifikasi operator selesai; jangan menampilkan CD/backup sukses palsu. Setelah capture immutable, aplikasi tidak perlu ditahan sepanjang upload manual. Ruang SSD100GB bebas saat dilaporkan diperiksa ulang untuk build/capture/download/restore; tidak purge volume/cadangan otomatis. D-31 menetapkan jadwal/retensi3lokal/7harian+4mingguanDrive; target formal RPO/RTO dikeluarkan D-32, backup/restore fungsional tetap belum diuji dan tidak ada waktu pemulihan yang dijanjikan. Semua operasi NOT RUN.

D-31: ikuti [jadwal/retensi kanonis](DATA_RECOVERY_PLAN.md) setelah demo/hari aktif dan sebelum perubahan berisiko. Pertahankan set mingguan saat label harian bergeser; verifikasi pengganti/remote serta set recoverable sebelum rotasi. Tidak melakukan pembersihan otomatis atau menurunkan retensi ketika ruang penuh. Bukti backup/rotasi/restore masih NOT RUN.

D-33 melengkapi smoke publik: verifikasi zone `<nama>.dpdns.org` yang benar-benar diterima, route sia/ws saudara, DNS dan certificate kedua host, redirect/login/Secure host-only cookie/trusted proxy, private PDF negatif dan WSS/private-channel/reconnect. Jangan mengartikan sertifikat *.dpdns.org sebagai bukti cakupan host bertingkat atau melewati validasi TLS. Kunci hostname saat build aset; jangan mengganti endpoint tertanam pada image yang sudah diperiksa. Mode sleep off selama sesi yang diotorisasi. Semua DNS/TLS/public smoke NOT RUN.
